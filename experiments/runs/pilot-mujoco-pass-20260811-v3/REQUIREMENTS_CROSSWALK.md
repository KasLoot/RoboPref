# RoboPref experiment-suite requirements crosswalk

Status: implementation audit for calibration and Gate 1 preparation; **not a
claim that a pilot or locked experiment has run**. Audited 2026-08-11 against
the user specification, the normative
[suite design](documentation_snapshot/EXPERIMENT_SUITE_DESIGN.md.source), and repository source at Git
commit `4bdd81b9f51942e15635544b0c8bbfbfb5ec8537` with a dirty working tree.

Status terms are deliberately narrow:

- `VERIFIED-CAL`: implemented and supported by the named existing calibration
  artifact. Calibration is not publication outcome evidence.
- `IMPLEMENTED`: code and a named contract test/preflight target exist; a fresh
  consolidated test report and campaign evidence are still required.
- `PARTIAL`: some code or configuration exists, but the scientific requirement
  is not end-to-end complete.
- `OPEN`: required evidence or execution has not occurred.
- `BLOCKED`: locked execution would be invalid or fail closed until resolved.
- `DEFERRED-AUTH`: intentionally unavailable without separate human/real-robot
  authorization and safety/ethics evidence.

At this audit snapshot there was no `experiments/runs/` directory. Therefore no
row below is closed by a pilot, frozen manifest, exact approval, locked outcome,
or independent campaign audit. Test references identify verification targets;
they do not assert a current green test run unless a calibration artifact is
named. This snapshot must be refreshed after later pilot or analysis work.

## Hard blockers before a scientifically valid locked freeze

1. Execute and independently audit successful and controlled-failure pilots for
   every distinct path, including a live tunnel-disconnection/recovery retry and
   the publication runtime path.
2. Extend publication-valid execution beyond T5/NM02/MuJoCo to every scheduled
   topology, ablation, baseline, scenario, trigger, and model-sensitivity cell,
   or explicitly version a scientifically justified protocol change before
   approval. The current engine correctly fails closed; it is not a full-suite
   runner.
3. Regenerate the implemented binary GLMM on immutable raw pilot artifacts,
   freeze every outcome-specific factor/reference/diagnostic/configuration, and
   execute the prespecified ≥1,000-simulation power curves. Implement any
   nonbinary model family that remains a claimed analysis. Paired summaries are
   useful but are not a substitute.
4. Resolve and freeze three exact VLM backbones, tokenizer/model hashes,
   decoding/serving parameters, prompts, schemas, and service identities.
5. Use pilot data to select `r`, and replace sensitivity estimates with measured
   call counts, durations, bitrates, artifact sizes, compute, and storage safety
   margins.
6. Finalize the draft preregistration, rerun the full tests/preflights from the
   final source, create the immutable schedule/campaign, and audit its hashes.
7. Extend the manifest-bound `production-mujoco` start/resume path so its
   publication engine behavior covers the entire frozen schedule.

Only after those blockers close can Gate 1 truthfully present a campaign ID,
protocol SHA-256, exact locked command, and representative audited artifacts.
Locked execution must then remain stopped until the user supplies the exact
matching approval sentence.
